# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-02-09
**Phases:** 1-4
**Total Plans:** 4

## Overview

Transform MonkeyLines from a functional prototype into a visually authentic Monkey Island experience. Four phases move from visual foundation (palette, font) through interactive controls and scene framing to final polish, each building on the previous. The result is a portfolio-ready piece with cohesive SCUMM-era aesthetic.

## Phases

### Phase 1: Visual Foundation

**Goal:** The page looks and feels like a Monkey Island screen — colors, typography, and base styling establish the retro aesthetic before any component work begins
**Depends on:** Nothing (first phase)
**Requirements:** VFND-01, VFND-02, VFND-03, VFND-04
**Plans:** 1 plan

**Success Criteria:**
1. Page background, text, and containers use deep purples/teals/ambers from the MI palette — no default browser colors remain
2. All text renders in a pixel font with crisp edges (no antialiasing smoothing visible)
3. All pixel art elements scale without blurring at any viewport size

Plans:
- [x] 01-01: MI color palette, pixel font, and base theme applied to all elements

**Details:**
- MI color palette defined as 10 CSS custom properties on :root
- Press Start 2P pixel font self-hosted as WOFF2 with font-display swap
- All page elements themed: backgrounds, borders, text, buttons, active states
- Anti-aliasing disabled for authentic retro pixel aesthetic

### Phase 2: Control Panel

**Goal:** Users interact with buttons that look like SCUMM verb bar controls — recognizable, themed, and intuitive on both desktop and mobile
**Depends on:** Phase 1
**Requirements:** CTRL-01, CTRL-02, CTRL-03, CTRL-04
**Plans:** 1 plan

**Success Criteria:**
1. Buttons display pixel art icons instead of emoji, styled in the MI palette
2. Controls sit in a dark verb bar panel below the scene, visually separated from the viewport
3. Every button is comfortably tappable on a phone (no mis-taps, no squinting)

Plans:
- [x] 02-01: Hybrid verb bar with text labels (Fight/Auto) and speaker icon (mute)

**Details:**
- Replaced emoji/SVG button icons with SCUMM-authentic text labels ("Fight", "Auto", "Mute")
- Built verb bar with proper CSS structure and dark panel styling
- Decided text labels over icons after pixel art rendering issues (more authentic to SCUMM)

### Phase 3: Scene and Speech

**Goal:** The monkey scene and speech text feel like a framed game viewport with character-attributed dialog
**Depends on:** Phase 1
**Requirements:** SCNE-01, SCNE-02, SCNE-03, SCNE-04
**Plans:** 1 plan

**Success Criteria:**
1. A visible border or frame surrounds the monkey scene, creating a "screen within screen" effect
2. Speech text color differs per monkey head so the viewer can tell who is speaking
3. Speech bubble has a pixel-art styled border that scales correctly and does not break text fitting
4. Scalable 9-slice borders render without stretching or blurring artifacts

Plans:
- [x] 03-01: Scene frame with pixel-art border, per-speaker text colors on existing bubble

**Details:**
- Monkey scene framed with decorative 24x24 pixel-art 9-slice border using MI palette
- Speech text now colored per speaking monkey head (amber L, teal C, orange R)
- Speech bubble restyled with 12x12 pixel-art border and dark background for readability
- Used inline base64 data URIs for border PNGs to avoid extra asset files

### Phase 4: Polish

**Goal:** Subtle retro effects add finishing authenticity without hurting usability
**Depends on:** Phase 3
**Requirements:** PLSH-01
**Plans:** 1 plan

**Success Criteria:**
1. A CRT scanline effect is visible on desktop but does not reduce text readability
2. The overlay performs smoothly on mobile (no jank or dropped frames)

Plans:
- [x] 04-01: CRT scanline overlay via CSS pseudo-element with accessibility support

**Details:**
- CRT scanline effect via CSS ::before pseudo-element on .monkey-scene
- Subtle 6px repeating gradient pattern at 0.2 opacity for authentic retro look
- Accessibility support via prefers-reduced-motion (opacity halved)
- Proper z-index layering: scanlines below speech text, pointer-events none

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Self-hosted font over Google Fonts CDN | Zero external dependencies for reliability | ✓ Good |
| CSS custom properties on :root for palette | Reusable theming pattern across all phases | ✓ Good |
| Text labels over pixel art icons for buttons | SCUMM authenticity + readability after icon rendering issues | ✓ Good |
| Inline base64 data URIs for border PNGs | No extra asset files to manage | ✓ Good |
| 6px scanline pattern (adjusted from 4px) | Better visibility at default zoom based on user feedback | ✓ Good |
| Opacity reduction (not removal) for reduced-motion | Maintains visual consistency while respecting accessibility | ✓ Good |

**Issues Resolved:**

- SVG/PNG pixel art icons produced unrecognizable rendering — resolved by switching to text labels (more authentic)
- Initial 4px scanline pattern too fine at 100% zoom — increased to 6px for better visibility
- Speech text readability with dark bubble — changed default color from --mi-text-dark to --mi-text

**Issues Deferred:**

- None — all v1 requirements shipped successfully

**Technical Debt Incurred:**

- None — clean implementation with no shortcuts requiring future rework
